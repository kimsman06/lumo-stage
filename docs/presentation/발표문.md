# LumoStage 프로젝트 발표문

**발표 시간:** 5분
**발표자:** 김재준

---

## 발표 시작 (10초)

안녕하세요. 아주대학교 웹 프로그래밍 응용 과목을 수강한 김재준입니다.

오늘 발표할 프로젝트는 **LumoStage**로, 웹 기반 실시간 3D 조명 시뮬레이션 플랫폼입니다.

---

## 1. 프로젝트 개요 (40초)

먼저 이 프로젝트를 시작하게 된 배경을 말씀드리겠습니다.

영상이나 영화를 촬영할 때 가장 중요한 요소 중 하나가 조명입니다. 하지만 실제 촬영 현장에서 조명을 설치하고 테스트하는 데는 많은 시간과 비용이 듭니다.

전문 3D 소프트웨어인 Cinema 4D나 Blender를 사용하면 미리 시뮬레이션할 수 있지만, 이런 프로그램들은 고가이고 학습 곡선도 가파릅니다. 특히 영상 제작을 처음 배우는 학생들이나 독립 영화 제작자들에게는 접근성이 낮습니다.

그래서 저는 **웹 브라우저에서 바로 사용할 수 있는 3D 조명 시뮬레이터**를 만들기로 했습니다. 설치 없이 즉시 접근할 수 있고, 실제 촬영 전에 조명과 카메라 구도를 실시간으로 시뮬레이션할 수 있는 도구입니다.

---

## 2. 기술 스택 (50초)

이 프로젝트는 MERN 스택을 기반으로 개발했습니다.

프론트엔드는 **React**와 **Vite**를 사용했고, 3D 렌더링은 **Three.js**와 **React-Three-Fiber**로 구현했습니다. 상태 관리는 **Zustand**를 사용해서 단방향 데이터 흐름을 유지했습니다. UI는 **Tailwind CSS**와 **shadcn/ui** 컴포넌트 라이브러리로 모던한 디자인을 구현했습니다.

백엔드는 **Node.js**와 **Express**로 REST API 서버를 만들었고, MVCS 패턴을 적용해서 유지보수성을 높였습니다. 데이터베이스는 **MongoDB**를 사용했고, 파일 스토리지는 **Cloudflare R2**를 사용했습니다. 인증은 Session 기반에 **Passport.js**로 Google과 Naver 소셜 로그인을 지원합니다.

특별히 Phase 7에서는 **Gemini 2.5 Flash Image API**를 통합해서 3D 조명 씬을 실사 이미지로 변환하는 AI 프리비주얼 기능을 구현했습니다. 비동기 처리를 위해 **Bull Queue**와 **Redis**를 사용했습니다.

아키텍처의 핵심은 **단방향 데이터 흐름**입니다. UI 컴포넌트에서 사용자 입력이 발생하면, Zustand Store를 통해 상태가 업데이트되고, 3D Scene이 자동으로 리렌더링됩니다. 이렇게 하면 상태가 예측 가능하고 디버깅도 쉽습니다.

---

## 3. 주요 기능 (1분 10초)

이 프로젝트는 총 7개의 Phase로 나눠서 개발했습니다. 주요 기능을 소개하겠습니다.

먼저 **실시간 3D 조명 시뮬레이션**입니다. Point, Spot, Directional, Rect Light 등 다양한 조명을 추가할 수 있고, 위치, 색상, 강도, 각도를 실시간으로 조정할 수 있습니다. 디퓨저 시스템도 구현해서 조명을 필터링하거나 2차 광원 효과를 만들 수 있습니다.

**카메라 제어** 기능도 있습니다. Phase 4에서는 Cinema 4D 스타일의 Camera-Orbit 동기화를 구현했습니다. 사용자가 OrbitControls로 탐색한 시점을 카메라 뷰로 바로 설정하거나, 반대로 카메라 뷰 위치로 OrbitControls를 이동시킬 수 있습니다.

Phase 5에서는 **배경 및 환경 시스템**을 구축했습니다. HDRI 파일을 업로드하면 실제 촬영 환경처럼 환경광이 적용됩니다. GLB 3D 오브젝트도 업로드해서 배치할 수 있습니다. 파일은 Cloudflare R2에 저장됩니다.

**프로젝트 관리** 기능도 완벽하게 구현했습니다. 조명, 카메라, 오브젝트 등 씬의 모든 상태를 저장하고 불러올 수 있습니다. 공유 토큰을 발급하면 다른 사람과 프로젝트를 공유할 수도 있습니다.

Phase 6에서는 **전문가용 UI**를 만들었습니다. 좌측에 Outliner 패널로 계층 트리를 보여주고, 우측에 Properties Panel로 선택된 객체를 상세하게 편집할 수 있습니다. 하단에는 Toolbar를 만들어서 Transform 모드를 전환하고, Undo/Redo 기능을 제공합니다.

초보자를 위해서는 Phase 4에서 **8단계 인터랙티브 튜토리얼**을 만들었습니다. 신규 사용자가 처음 들어오면 자동으로 실행되고, 5분 안에 핵심 기능을 모두 익힐 수 있습니다.

마지막으로 Phase 7에서 구현한 **AI 프리비주얼** 기능입니다. 사용자가 만든 3D 조명 씬을 Gemini API로 실사 이미지로 변환할 수 있습니다. 영화 스토리보드나 프리비주얼 제작에 활용할 수 있습니다.

## 4. 어려웠던 점 (1분 20초)

개발 과정에서 세 가지 큰 어려움이 있었습니다.

첫 번째는 **OrbitControls와 Camera 상태 동기화**입니다.

Three.js의 OrbitControls는 자체적으로 카메라를 조작하는데, 이 상태를 프로젝트에 저장하고 복원하는 게 어려웠습니다. 특히 사용자가 탐색한 시점을 "카메라 뷰"로 설정하는 기능이 필요했습니다.

이 문제를 해결하기 위해 Cinema 4D 스타일의 양방향 동기화를 구현했습니다. `setOrbitToCameraView`와 `setCameraViewToOrbit` 함수를 만들어서 OrbitControls의 카메라 위치와 타겟을 Zustand Store에 저장하고, 반대로 Store의 카메라 상태를 OrbitControls에 적용하도록 했습니다.

그 결과 프로젝트 저장/로드 시 OrbitControls 위치도 100% 정확하게 복원됩니다.

두 번째는 **대용량 파일 업로드 및 관리**입니다.

HDRI 파일은 최대 50MB, GLB 파일은 최대 100MB인데, 로컬 서버 디스크에 저장하면 용량 문제가 생깁니다. 또한 프로젝트 삭제 시 연결된 파일도 함께 삭제해야 합니다.

이를 위해 Cloudflare R2 스토리지를 사용했습니다. S3 호환 API를 사용해서 Multer로 받은 메모리 버퍼를 직접 R2로 업로드합니다. Asset 모델로 파일 메타데이터를 관리하고, cascade 삭제를 구현해서 프로젝트 삭제 시 연결된 에셋도 자동으로 삭제되도록 했습니다.

결과적으로 HDRI 업로드 성공률이 99% 이상이고, 업로드 시간도 50MB 기준 10초 이내로 매우 빠릅니다.

세 번째는 **Scene 데이터 정규화**입니다.

초기에는 프로젝트 A의 조명이 프로젝트 B에 나타나는 버그가 있었습니다. 클라이언트에서 전송한 데이터에 불필요한 필드가 포함되어 있었기 때문입니다.

이 문제는 서버의 `scene.service.normalizeSceneData()` 함수로 해결했습니다. 모든 프로젝트 엔드포인트에서 이 함수를 호출해서 필요한 필드만 추출하고, 기본값을 제공해서 역호환성도 유지했습니다.

## 5. 특별히 고민한 부분 (50초)

개발하면서 특별히 고민한 부분은 두 가지입니다.

첫 번째는 **초보자와 전문가 모두를 위한 UX**입니다.

영상 전공 학생은 3D 툴 경험이 적은 반면, 전문 촬영감독은 Cinema 4D 같은 전문 UI를 원합니다.

그래서 Phase 4에서 8단계 인터랙티브 튜토리얼을 만들어서 신규 사용자가 5분 안에 핵심 기능을 익힐 수 있도록 했습니다. 동시에 Phase 6에서 Outliner, Properties Panel, Toolbar를 구현해서 전문가도 효율적으로 작업할 수 있도록 했습니다.

두 번째는 **단방향 데이터 흐름 유지**입니다.

3D Scene 컴포넌트와 UI 컨트롤 패널 간 상태 동기화가 복잡할 수 있는데, Zustand 중앙 상태 관리를 통해 UI 컴포넌트에서 Zustand 액션을 호출하면 3D Scene이 자동으로 업데이트되도록 했습니다. 양방향 바인딩 대신 단방향 데이터 흐름을 유지해서 상태를 예측 가능하게 만들었습니다.

## 6. 난이도가 높았던 구현 요소 (50초)

난이도가 특히 높았던 구현 요소는 세 가지입니다.

첫 번째는 **Undo/Redo 시스템**입니다.

Zustand 상태 전체를 스냅샷으로 저장해야 하는데, Transform 드래그 중에는 저장하지 않고 완료 시에만 저장해야 했습니다. Zustand temporal middleware를 사용해서 최대 50개까지 히스토리를 관리하고, 메모리 효율적으로 구현했습니다.

두 번째는 **Gemini API 통합 및 암호화**입니다.

사용자가 직접 입력한 Gemini API 키를 안전하게 저장해야 했습니다. AES-256-GCM 암호화 알고리즘을 사용해서 IV를 매번 랜덤으로 생성하고, authTag로 무결성을 검증했습니다. 이렇게 하면 DB가 해킹당해도 API 키를 복호화할 수 없습니다.

세 번째는 **Cloudflare R2 파일 스토리지**입니다.

S3 호환 API 사용법을 학습하고, Multer 메모리 스토리지에서 직접 R2로 업로드하는 파이프라인을 구축했습니다. 테스트 환경에서는 R2 모킹을 구현해서 자동화 테스트를 성공시켰습니다.

## 예상 질문 및 답변

### Q1: 왜 WebGL이 아닌 Three.js를 선택했나요?
**A**: Three.js는 WebGL을 추상화한 라이브러리로, 직접 WebGL을 사용하는 것보다 개발 속도가 훨씬 빠릅니다. 또한 React-Three-Fiber를 사용하면 React 컴포넌트처럼 3D Scene을 선언적으로 작성할 수 있어서 유지보수가 쉽습니다.

### Q2: Zustand 대신 Redux를 사용하지 않은 이유는?
**A**: Zustand는 보일러플레이트가 적고, TypeScript 지원이 우수하며, 성능도 우수합니다. Redux는 대규모 애플리케이션에 적합하지만, 이 프로젝트 규모에서는 Zustand가 더 효율적이라고 판단했습니다.

### Q3: Cloudflare R2를 선택한 이유는?
**A**: AWS S3보다 비용이 저렴하고, Egress(다운로드) 비용이 무료입니다. S3 호환 API를 제공해서 기존 S3 SDK를 그대로 사용할 수 있었습니다.

### Q4: AI 프리비주얼 기능은 어떻게 활용할 수 있나요?
**A**: 영화 제작 프리프로덕션 단계에서 촬영 전 조명 테스트 결과를 실사 이미지로 변환해서 감독이나 촬영감독과 커뮤니케이션할 수 있습니다. 유튜버는 조명 세팅을 미리 시뮬레이션해서 실제 촬영 환경을 예측할 수 있습니다.

### Q5: 향후 계획은?
**A**: Phase 8에서는 기술 부채 정리와 E2E 테스트를 진행할 예정입니다. Phase 9에서는 실시간 멀티 유저 편집 기능을 추가하고, Phase 10에서는 포스트 프로세싱 효과를 구현할 계획입니다. 장기적으로는 Freemium 비즈니스 모델로 전환할 예정입니다.
