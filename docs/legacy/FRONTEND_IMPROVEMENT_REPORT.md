# LumoStage 프론트엔드 개선 보고서

**작성일:** 2025년 10월 26일
**작성자:** Gemini (프론트엔드 코드 리뷰 전문가)

## 1. 개요

본 문서는 LumoStage 프로젝트의 현재 프론트엔드 구현 상태를 디자인 전략, 아키텍처, 코드 품질 관점에서 종합적으로 검토하고, 향후 개선 방향을 제시하는 것을 목표로 합니다. 전반적으로 프로젝트는 매우 훌륭한 설계와 구현을 바탕으로 하고 있으며, 본 보고서는 이를 더욱 발전시키기 위한 제안들입니다.

---

## 2. 디자인 및 UI/UX 일관성 (Design & UI/UX Consistency)

**종합 평가: (우수)** `DesignStrategy.md`에 정의된 'Digital Cinematography Studio' 컨셉이 UI 전반에 잘 반영되어 있습니다. `shadcn/ui`를 기반으로 한 커스텀 테마와 컴포넌트들이 일관성 있게 사용되고 있습니다.

| 항목 | 평가 | 상세 내용 및 제안 |
| --- | --- | --- |
| **색상 시스템** | ✅ **우수** | `tailwind.config.js`에 `studio`, `accent` 등 의미론적 색상 정의가 누락되어 있습니다. `DesignStrategy.md`의 팔레트를 `tailwind.config.js`에 반영하여, `bg-studio-900`과 같이 일관성 있는 클래스 사용을 권장합니다. (현재는 `bg-black/50` 등 직접적인 값 사용) |
| **타이포그래피** | ✅ **우수** | `Pretendard`와 `Inter` 폰트 시스템이 잘 설정되어 있으며, 헤딩 및 본문 스케일이 일관되게 적용되고 있습니다. |
| **레이아웃** | ✅ **우수** | `EditorPage`는 디자인 문서의 2단 레이아웃(3D 뷰포트 + 에디터 패널)을 정확히 구현하고 있습니다. |
| **컴포넌트 스타일** | ⚠️ **개선 필요** | `LightCard.jsx`의 컬러 피커가 `Popover`를 사용하는 대신 `<input type="color">`의 기본 UI를 직접 노출하고 있습니다. `DesignStrategy.md`의 명세대로 `Popover`와 커스텀 컬러 피커를 조합하여 디자인 통일성을 높일 필요가 있습니다. |
| **마이크로 인터랙션** | ⚠️ **개선 필요** | `ProjectCard.jsx` 등에서 `group-hover`를 사용한 인터랙션은 훌륭하나, `DesignStrategy.md`에 정의된 `hover:scale-105`와 같은 입체적인 효과는 적용되지 않았습니다. `tailwindcss-animate`를 활용하여 더 풍부한 피드백을 제공할 수 있습니다. |

## 3. 기능 및 코드 품질 (Functionality & Code Quality)

**종합 평가: (양호)** `Zustand`를 활용한 상태 관리가 효율적으로 이루어지고 있으나, 일부 컴포넌트의 복잡도와 잠재적인 성능 이슈가 발견되었습니다.

| 항목 | 평가 | 상세 내용 및 제안 |
| --- | --- | --- |
| **상태 관리** | ✅ **우수** | `authStore`, `projectStore`, `editorStore`로 도메인별 상태 분리가 잘 되어 있습니다. 비동기 로직 처리(로딩, 에러 상태)도 일관성 있게 구현되었습니다. |
| **컴포넌트 복잡도** | ⚠️ **개선 필요** | `Scene.jsx` 컴포넌트가 조명, 마네킹, 기즈모, 그리드 등 너무 많은 3D 요소를 직접 렌더링하고 관리하여 비대합니다. `Lights.jsx`, `Mannequins.jsx`, `Gizmo.jsx` 등 하위 컴포넌트로 분리하여 가독성과 유지보수성을 높이는 리팩토링을 권장합니다. |
| **성능 최적화** | ⚠️ **개선 필요** | `LightCard`와 같이 리스트 형태로 렌더링되는 컴포넌트에 `React.memo`를 적용하여, 불필요한 리렌더링을 방지해야 합니다. 현재는 하나의 조명 값만 변경되어도 모든 카드가 리렌더링될 수 있습니다. |
| **하드코딩된 값** | ❌ **수정 필요** | `LoginPage.jsx`의 소셜 로그인 버튼에 백엔드 주소(`http://localhost:4000`)가 하드코딩되어 있습니다. 이는 배포 환경에서 문제를 일으키므로, `.env` 파일의 환경 변수(`VITE_API_URL`)를 사용하도록 즉시 수정해야 합니다. |
| **불필요한 요소** | ❔ **확인 필요** | `ProjectCard.jsx`에 `viewMode`라는 prop이 있으나, 현재 대시보드에서는 항상 동일한 모드로 렌더링됩니다. 향후 리스트/그리드 뷰 전환 기능을 위한 것이 아니라면 제거하는 것을 고려할 수 있습니다. |

## 4. 누락된 기능 및 향후 추천 기능

### 4.1 계획되었으나 누락된 기능

`DesignStrategy.md`와 현재 구현 상태를 비교했을 때, 다음 기능들이 아직 구현되지 않았습니다.

1.  **에디터 헤더의 Scene Title 수정**: 현재 `EditorPage` 헤더에 프로젝트 이름이 표시되지만, 이를 직접 수정하는 `Input` 기능이 누락되었습니다.
2.  **공유(Share) 기능**: 헤더의 `Share` 버튼이 존재하지만, 실제 공유 다이얼로그나 기능은 구현되지 않았습니다.
3.  **토스트 피드백 시스템**: `sonner` 컴포넌트는 추가되었으나, `projectStore` 등에서 API 호출 성공/실패 시 토스트 메시지를 띄워주는 로직이 아직 연동되지 않았습니다. (현재는 `alert()` 사용)
4.  **3D 뷰포트 오버레이**: 뷰포트 좌측 하단에 현재 조명 개수 등을 표시하는 `Badge` UI가 누락되었습니다.

### 4.2 향후 추천 기능

LumoStage를 더욱 강력한 도구로 만들어 줄 다음과 같은 기능들을 제안합니다.

1.  **에디터 내 Undo/Redo (되돌리기/다시 실행)**: `zustand-middleware-immer`와 같은 라이브러리를 활용하여 모든 상태 변경을 추적하고, 사용자가 쉽게 이전 작업으로 되돌릴 수 있는 기능을 제공합니다. (사용자 경험에 가장 큰 영향을 줄 기능)
2.  **에셋 라이브러리**: 다양한 3D 모델(가구, 소품 등)과 조명 프리셋을 사용자가 쉽게 불러와 장면에 배치할 수 있는 패널을 추가합니다.
3.  **렌더링 결과물 Export**: 현재 씬을 고해상도 이미지(PNG, JPG) 또는 비디오(MP4)로 렌더링하여 내보내는 기능을 제공합니다.
4.  **실시간 협업**: 여러 사용자가 하나의 씬에 동시에 접속하여 함께 조명을 편집할 수 있는 기능을 `WebSockets` (또는 `Liveblocks`, `PartyKit` 등)을 통해 구현합니다.

## 5. 종합 요약 및 우선순위 제안

LumoStage는 **체계적인 설계와 견고한 초기 구현**이 돋보이는 프로젝트입니다. 특히, 상세한 디자인/아키텍처 문서는 향후 프로젝트가 나아갈 방향을 명확히 제시하고 있습니다.

**단기적으로 다음 개선사항들을 우선적으로 처리할 것을 제안합니다.**

1.  **(즉시) 하드코딩된 API 주소 수정**: 배포를 위해 환경 변수 사용이 시급합니다.
2.  **(높음) 주요 컴포넌트 리팩토링**: `Scene.jsx`을 분리하고 `LightCard` 등에 `React.memo`를 적용하여 코드 품질과 성능의 기반을 다집니다.
3.  **(높음) 디자인 시스템 연동**: `tailwind.config.js`에 색상 팔레트를 적용하고, `Popover`를 이용한 컬러 피커를 구현하여 디자인 통일성을 완성합니다.
4.  **(중간) 누락된 UI 기능 구현**: Scene Title 수정, 공유 버튼, 토스트 피드백 등 계획되었던 UI 기능들을 구현하여 완성도를 높입니다.

위 개선사항들이 완료되면, LumoStage는 기술적으로나 사용자 경험 측면에서 한 단계 더 높은 수준의 애플리케이션이 될 것입니다.
